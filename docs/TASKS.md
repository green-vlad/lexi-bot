# lexi-bot — бэклог задач

Разбивка [плана](./PLAN.md) на последовательные задачи. Каждая — примерно 1–3 часа,
оставляет репозиторий в собирающемся и проходящем тесты состоянии.
Идём сверху вниз; задачи внутри одной вехи, помеченные `∥`, можно делать параллельно.

Обозначения: **DoD** — критерий готовности. Отмечайте `[x]` по мере выполнения.

## M1 — Домен (без БД и без Telegram)

Самая ценная веха: здесь живёт вся логика обучения, и она полностью тестируема в памяти.

- [x] **T-006. `domain/lexicon`**
  `Language` (валидация BCP-47), `Lexeme`, `Translation`, `Deck`, `DeckItem`. Конструкторы с валидацией (пустой `term` недопустим, `lang_code` обязателен).
  **DoD:** таблично протестированы конструкторы и ошибки валидации; пакет не импортирует ничего из проекта.

- [x] **T-007. `domain/user`** ∥
  `User`, `UILang`, `Timezone` (обёртка над `*time.Location`), `Settings` с границами (`new_per_day` 1..100, `max_reviews_per_day` 10..500). Метод `Settings.DayStart(t time.Time) time.Time` — начало суток пользователя.
  **DoD:** тесты на границы, на переход через полночь и на смену таймзоны.

- [x] **T-008. `domain/study`: типы**
  `Rating` (Again/Hard/Good/Easy), `State` (New/Learning/Review/Relearning/Suspended), `CardState`, `Card`, `Review`, интерфейс `Scheduler`.
  **DoD:** `String()` и разбор из строки для `Rating`/`State` протестированы в обе стороны.

- [x] **T-009. Алгоритм SM-2** ⭐
  Реализация `Scheduler`: learning-шаги (1 мин, 10 мин), graduating interval 1 д, easy interval 4 д, EF по формуле SM-2 с полом 1.3, обработка провала (Relearning, `lapses++`, интервал × 0.5), небольшой джиттер интервала через инжектируемый `Rand`.
  **DoD:** табличные тесты на каждый переход состояний; эталонная последовательность из 10 повторений даёт зафиксированные в тесте интервалы; `Next` не обращается к `time.Now()`; покрытие пакета ≥ 95%.

- [x] **T-010. Нормализация и сравнение ответа** ∥
  NFC → нижний регистр → схлопывание пробелов и пунктуации → отсечение артиклей/`to `. Расстояние Левенштейна. Сравнение со списком допустимых переводов.
  **DoD:** тесты на кейсы `«Человек» == «человек »`, `«the house» == «house»`, опечатка на 1 символ = «почти верно», разные значения через `;` засчитываются все.

- [x] **T-011. Отображение ответа в оценку**
  `RatingResolver`: `(mode, correct, elapsed, editDistance) → Rating` по таблице из плана (§5).
  **DoD:** таблично покрыты все три режима, включая «верно и быстро → Easy» и «опечатка → Hard».

## M4 — Telegram: каркас и онбординг

- [x] **T-022. Транспорт**
  Порт `Messenger` (`SendMessage`, `EditMessage`, `AnswerCallback`, `SendDocument`, `DownloadFile`), адаптер на `github.com/go-telegram/bot`, цикл long polling, graceful shutdown по сигналу.
  **DoD:** бот отвечает `pong` на `/ping` в реальном чате; по `SIGTERM` завершает обработку текущих апдейтов и закрывает пул.

- [x] **T-023. Роутер и middleware**
  Диспетчеризация команд / текста / callback'ов. Middleware: восстановление после паники, логирование с `update_id`, определение пользователя (авторегистрация), подстановка `Localizer` по `ui_lang`.
  **DoD:** юнит-тесты на фейковом `Messenger`; паника в хендлере не роняет процесс и даёт пользователю сообщение об ошибке.

- [x] **T-024. Движок FSM** ∥
  Переходы состояний поверх `SessionRepo`, отмена по `/cancel`, защита от «застрявшего» состояния.
  **DoD:** тесты на полный цикл диалога и на прерывание командой посреди диалога.

- [x] **T-025. Клавиатуры и кодек callback-данных** ∥
  Компактный формат `действие:id:параметр` (≤ 64 байт), сборка inline-клавиатур, обязательный `answerCallbackQuery`.
  **DoD:** тесты кодирования/декодирования, включая проверку превышения лимита длины; property-тест на обратимость.

- [x] **T-026. `usecase/onboarding`**
  Регистрация, выбор языка изучения → колоды → языка перевода; создание `user_course`. Язык интерфейса определяется по клиенту Telegram и спрашивается, только если не определился; `new_per_day`, таймзона и напоминание получают значения по умолчанию и настраиваются потом через `/settings` — семь экранов до первого выученного слова это семь возможностей передумать.
  **DoD:** юнит-тесты на фейковых репозиториях; повторный `/start` у существующего пользователя не сбрасывает прогресс.

- [x] **T-027. Хендлер `/start`**
  Диалог онбординга на клавиатурах, с возможностью вернуться на шаг назад.
  **DoD:** тесты сценария целиком на фейках; все тексты приходят из локалей.

- [x] **T-028. `/help` и `/language`** ∥
  Справка и смена языка интерфейса на лету.
  **DoD:** после смены языка следующее сообщение приходит на новом языке.

## M5 — Учебная сессия

- [x] **T-029. `usecase/session`: формирование очереди** ⭐
  Порядок «просроченные → обучающиеся → новые», лимиты `max_reviews_per_day` и остаток `new_per_day`, выбор режима проверки для карточки.
  **DoD:** юнит-тесты: лимит новых соблюдается; после исчерпания очереди возвращается «на сегодня всё»; смена суток в TZ пользователя обнуляет лимит.

- [x] **T-030. `usecase/session`: приём ответа** ⭐
  Проверка ответа → `RatingResolver` → `Scheduler.Next` → запись `review` и нового состояния карточки в одной транзакции; идемпотентность по токену попытки.
  **DoD:** юнит-тесты, включая двойную отправку одного и того же ответа (второй раз состояние не меняется) и провал карточки (переход в Relearning, `lapses++`).

- [x] **T-031. Режим «помню / не помню»**
  Слово → «Показать перевод» → кнопки оценки.
  **DoD:** тест хендлера на фейках: правильный текст, правильная клавиатура, вызов use-case с ожидаемой оценкой.

- [x] **T-032. Режим «выбор из 4»**
  Генератор дистракторов (та же колода, по возможности та же часть речи, без совпадений с правильным ответом после нормализации), инжектируемый `Rand`.
  **DoD:** тесты: ровно 4 варианта, правильный всегда среди них, дистракторы не дублируются; при малой колоде (< 4 слов) есть корректный запасной вариант.

- [ ] **T-033. Режим ввода текстом**
  Приём текстового сообщения как ответа, подсветка расхождения, показ всех допустимых переводов.
  **DoD:** тесты на точное совпадение, опечатку и неверный ответ; посторонняя команда во время ожидания ответа не считается ответом.

- [ ] **T-034. Завершение сессии** ∥
  Сводка: сколько повторено, сколько новых, точность, когда следующее повторение.
  **DoD:** тест на корректность чисел в сводке.

## M8 — Настройки, статистика, напоминания

- [ ] **T-044. Настройки**
  `usecase/settings` + `/settings`: слов в день, лимит повторений, включённые режимы проверки, время напоминания, таймзона, обратное направление (перевод → слово).

- [ ] **T-046. Планировщик и outbox** ⭐
  `robfig/cron` с тиком в 5 минут, отбор пользователей по локальному времени, вставка в `outbox_notifications` в транзакции, `pg_try_advisory_lock` против дублей при нескольких инстансах.

- [ ] **T-047. Рассылка**

  **DoD:** тест ограничителя; при `403` пользователь помечается неактивным и рассылка продолжается.

- [ ] **T-048. `/pause` и `/delete_me`** ∥
  Пауза обучения и полное удаление данных пользователя с подтверждением.
  **DoD:** интеграционный тест: после удаления в БД не остаётся строк, связанных с пользователем.

## M9 — Продакшен

Детали решений — в [DEPLOY.md](./DEPLOY.md).

- [ ] **T-049. Наблюдаемость**
  `/healthz` (пул БД + время последнего успешного polling-цикла) и `/metrics` Prometheus (апдейты, ответы по режимам, задержки БД, ошибки Telegram API) на локальном интерфейсе. Алерты в админский чат (`ADMIN_CHAT_ID`): паника, ошибка миграции, серия ошибок Telegram API.
  **DoD:** метрики отдаются, healthcheck краснеет при погашенной БД, тестовый алерт доходит в админский чат.

- [ ] **T-050. Сборка образа**
  Многостадийный `Dockerfile` (distroless, статическая сборка, non-root), `.dockerignore`, публикация в GHCR из CI с тегами `sha-<полный SHA>` и `latest`, кеш сборки через `type=gha`.

## Порядок и зависимости

```
M0 ──► M1 ──► M2 ──► M4 ──► M5 ──► M6 ──► M7 ──► M8 ──► M9
        │      │      ▲
        └──────┴─ M3 ─┘
```

M1 (домен) не зависит ни от чего и делается полностью в памяти — это лучшая точка входа
в проект: после неё вся логика обучения уже написана и протестирована, остальное
подключает её к миру. M3 (локализация) нужна к началу M4.

**Первая работающая версия — после T-034:** онбординг, встроенная колода-заглушка,
учебная сессия со всеми тремя режимами и настоящим SM-2. Всё дальнейшее наращивает
её без переделок.
