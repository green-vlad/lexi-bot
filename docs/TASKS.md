# lexi-bot — бэклог задач

Разбивка [плана](./PLAN.md) на последовательные задачи. Каждая — примерно 1–3 часа,
оставляет репозиторий в собирающемся и проходящем тесты состоянии.
Идём сверху вниз; задачи внутри одной вехи, помеченные `∥`, можно делать параллельно.

Обозначения: **DoD** — критерий готовности. Отмечайте `[x]` по мере выполнения.

## M1 — Домен (без БД и без Telegram)

Самая ценная веха: здесь живёт вся логика обучения, и она полностью тестируема в памяти.

- [x] **T-006. `domain/lexicon`**
  `Language` (валидация BCP-47), `Lexeme`, `Translation`, `Deck`, `DeckItem`. Конструкторы с валидацией (пустой `term` недопустим, `lang_code` обязателен).
  **DoD:** таблично протестированы конструкторы и ошибки валидации; пакет не импортирует ничего из проекта.

- [x] **T-007. `domain/user`** ∥
  `User`, `UILang`, `Timezone` (обёртка над `*time.Location`), `Settings` с границами (`new_per_day` 1..100, `max_reviews_per_day` 10..500). Метод `Settings.DayStart(t time.Time) time.Time` — начало суток пользователя.
  **DoD:** тесты на границы, на переход через полночь и на смену таймзоны.

- [x] **T-008. `domain/study`: типы**
  `Rating` (Again/Hard/Good/Easy), `State` (New/Learning/Review/Relearning/Suspended), `CardState`, `Card`, `Review`, интерфейс `Scheduler`.
  **DoD:** `String()` и разбор из строки для `Rating`/`State` протестированы в обе стороны.

- [x] **T-009. Алгоритм SM-2** ⭐
  Реализация `Scheduler`: learning-шаги (1 мин, 10 мин), graduating interval 1 д, easy interval 4 д, EF по формуле SM-2 с полом 1.3, обработка провала (Relearning, `lapses++`, интервал × 0.5), небольшой джиттер интервала через инжектируемый `Rand`.
  **DoD:** табличные тесты на каждый переход состояний; эталонная последовательность из 10 повторений даёт зафиксированные в тесте интервалы; `Next` не обращается к `time.Now()`; покрытие пакета ≥ 95%.

- [x] **T-010. Нормализация и сравнение ответа** ∥
  NFC → нижний регистр → схлопывание пробелов и пунктуации → отсечение артиклей/`to `. Расстояние Левенштейна. Сравнение со списком допустимых переводов.
  **DoD:** тесты на кейсы `«Человек» == «человек »`, `«the house» == «house»`, опечатка на 1 символ = «почти верно», разные значения через `;` засчитываются все.

- [x] **T-011. Отображение ответа в оценку**
  `RatingResolver`: `(mode, correct, elapsed, editDistance) → Rating` по таблице из плана (§5).
  **DoD:** таблично покрыты все три режима, включая «верно и быстро → Easy» и «опечатка → Hard».

## M4 — Telegram: каркас и онбординг

- [x] **T-022. Транспорт**
  Порт `Messenger` (`SendMessage`, `EditMessage`, `AnswerCallback`, `SendDocument`, `DownloadFile`), адаптер на `github.com/go-telegram/bot`, цикл long polling, graceful shutdown по сигналу.
  **DoD:** бот отвечает `pong` на `/ping` в реальном чате; по `SIGTERM` завершает обработку текущих апдейтов и закрывает пул.

- [x] **T-023. Роутер и middleware**
  Диспетчеризация команд / текста / callback'ов. Middleware: восстановление после паники, логирование с `update_id`, определение пользователя (авторегистрация), подстановка `Localizer` по `ui_lang`.
  **DoD:** юнит-тесты на фейковом `Messenger`; паника в хендлере не роняет процесс и даёт пользователю сообщение об ошибке.

- [x] **T-024. Движок FSM** ∥
  Переходы состояний поверх `SessionRepo`, отмена по `/cancel`, защита от «застрявшего» состояния.
  **DoD:** тесты на полный цикл диалога и на прерывание командой посреди диалога.

- [x] **T-025. Клавиатуры и кодек callback-данных** ∥
  Компактный формат `действие:id:параметр` (≤ 64 байт), сборка inline-клавиатур, обязательный `answerCallbackQuery`.
  **DoD:** тесты кодирования/декодирования, включая проверку превышения лимита длины; property-тест на обратимость.

- [x] **T-026. `usecase/onboarding`**
  Регистрация, выбор языка изучения → колоды → языка перевода; создание `user_course`. Язык интерфейса определяется по клиенту Telegram и спрашивается, только если не определился; `new_per_day`, таймзона и напоминание получают значения по умолчанию и настраиваются потом через `/settings` — семь экранов до первого выученного слова это семь возможностей передумать.
  **DoD:** юнит-тесты на фейковых репозиториях; повторный `/start` у существующего пользователя не сбрасывает прогресс.

- [x] **T-027. Хендлер `/start`**
  Диалог онбординга на клавиатурах, с возможностью вернуться на шаг назад.
  **DoD:** тесты сценария целиком на фейках; все тексты приходят из локалей.

- [x] **T-028. `/help` и `/language`** ∥
  Справка и смена языка интерфейса на лету.
  **DoD:** после смены языка следующее сообщение приходит на новом языке.

## M7 — Слова пользователя

- [x] **T-039. `usecase/vocab`: добавление слова**
  Личная колода «Мои слова: <язык>» и курс под неё заводятся при первом добавлении; языки берутся из курса, который человек учит сейчас. Дедупликация тройная: слово из встроенного словаря берётся целиком вместо копии, повторное добавление ничего не создаёт, а слово из колоды, которая уже учится, отклоняется — копия означала бы две карточки на одно слово. Карточка при добавлении **не** создаётся: слово встаёт в очередь знакомства и проходит через «запомнил / уже знаю / пропустить», как любое другое (изменение против исходного DoD, следствие T-034в).
  **DoD:** юнит-тесты на все три вида дедупликации, на пустое слово и пустой перевод (ничего не записывается), на отсутствие курса.

- [x] **T-040. Диалог `/add`**
  Слово → перевод → опционально чтение и пример, у необязательных шагов кнопка «Пропустить». Слово можно передать сразу — `/add 냉장고`, — и тогда первый шаг пропускается. Несколько переводов — через `;` или `/`; запятая разделителем не служит, она чаще стоит внутри значения. Заодно название личной колоды стало показываться на языке интерфейса, а не на том, на котором её завели.
  **DoD:** тест диалога целиком, тест на слово из команды, тест на пропуск обоих необязательных шагов, тест на повтор вопроса при пустом вводе; `/cancel` посреди диалога не оставляет ни слова, ни колоды, ни курса.

- [x] **T-041. Парсер CSV** ∥
  `internal/adapter/importcsv`: UTF-8 с BOM и без, автоопределение разделителя `,`/`;` по знакам вне кавычек, обязательный заголовок, несколько переводов через `;` или `/`, ограничения 2 МБ и 5000 строк. Колонки ищутся **по именам**, а не по местам: порядок произвольный, имена русские или английские, лишние колонки игнорируются. Разбор частичный — годные строки возвращаются, негодные складываются в отчёт с номерами строк.
  **DoD:** табличные тесты: BOM, оба разделителя (в том числе `;` внутри кавычек), поиск колонок по именам, отсутствующие колонки, короткая строка, пустые строки, неизвестная часть речи, слишком длинные значения, оба предела и ровно предел, невалидный UTF-8.

- [x] **T-042. Use-case импорта**
  `internal/usecase/importing` поверх парсера и личного словаря: годные строки добавляются, битые попадают в отчёт с номерами и причинами. Повтор и слово из учебной колоды считаются отдельно от ошибок — человек мог прислать файл дважды. Задание пишется в `import_jobs` и на удачном импорте, и на провальном: сводка в чате теряется под следующими сообщениями, задание остаётся. Ошибка домена на строке — повод пропустить строку, поломка хранилища — повод остановиться. Заодно написан `postgres.ImportRepo`.
  **DoD:** юнит-тесты на смешанный файл (номера и причины в отчёте), на счёт повторов отдельно от ошибок, на остановку при поломке хранилища и при отсутствии курса, на битый файл целиком; интеграционный тест репозитория, включая поездку отчёта через JSONB.

- [x] **T-043. Хендлер `/import`**
  Диалога нет: файл можно прислать когда угодно, а `/import` только рассказывает, какой файл подойдёт. Размер и тип проверяются **до** скачивания. Тип определяется по MIME или расширению — некоторые редакторы отдают CSV как поток байтов. Сводка «загружено N, уже было M, не разобрано K» и отчёт об ошибках отдельным CSV-файлом с меткой порядка байтов, чтобы редактор таблиц открыл его в UTF-8. В роутер добавлен маршрут для присланных файлов.
  **DoD:** тесты на фейковом мессенджере со скачиванием: удачная загрузка, отчёт об ошибках с номерами строк, повтор отдельно от ошибок, слишком большой файл (не качается), не-CSV (не качается), CSV по расширению, нечитаемый файл, отсутствие курса, справка по команде.

## M8 — Настройки, статистика, напоминания

- [x] **T-034а. Направление проверки** ⭐
  `study.Direction`: «изучаемый → родной» (узнавание) и «родной → изучаемый» (воспроизведение), переключается в настройках. Ввод текстом разрешён только во втором направлении — у перевода на родной язык слишком много равноправных значений. Варианты для выбора берутся из того же, чем отвечают.
  **DoD:** тесты на фильтрацию режимов по направлению, на вопрос и ответ в обе стороны, на варианты выбора.

- [x] **T-034б. Один экран вопроса** ⭐
  Карточка спрашивается вариантами перевода, а рядом с ними — кнопка «напишу сам» для тех, кто хочет напечатать ответ. Режим самооценки убран целиком: отметку в нём ставил тот же, кого проверяли, и расписание строилось на его снисхождении к себе. Кнопка показывается только там, где ответ — слово изучаемого языка.
  **DoD:** тесты: кнопка есть в сторону изучаемого языка и её нет в обратную; нажатие убирает варианты и переводит бота в ожидание текста; в бедной колоде, где вариантов не набрать, слово спрашивается вводом текста.

- [x] **T-034в. Меню занятия и знакомство с новыми словами** ⭐
  `/learn` открывает меню из двух занятий: повторение начатых слов и знакомство с новыми. Знакомство показывает слово целиком — написание, чтение, переводы, пример — и предлагает три решения: «запомнил» (карточка уходит на первый шаг обучения), «я уже знаю это слово» (фаза `known`, слово больше не встретится) и «пропустить» (вернётся завтра). Повторение новых слов больше не вводит. Дневная норма — пять слов, и тратит её только «запомнил».
  **DoD:** тесты сценария на все три решения, дневную норму и конец колоды; тесты экранов на состав меню, карточку знакомства и возврат отложенного слова; интеграционные тесты очереди знакомства и гонки на «запомнил».

- [x] **T-044. Настройки**
  `usecase/settings` + `/settings`: слов в день, лимит повторений, включённые режимы проверки, время напоминания, таймзона, обратное направление. Экран один и правится на месте; частые значения закрыты кнопками, редкие набираются руками. Последний включённый режим выключить нельзя — карточку станет нечем показать. Дневная норма новых слов фиксируется в строке счётчика при её заведении, поэтому правка вступает в силу назавтра, а не задним числом. Заодно онбординг стал запоминать выбранный курс как текущий — раньше занятие работало через запасной путь «первый активный».
  **DoD:** тесты сценария на границы значений и на то, что отклонённая правка ничего не сохраняет; тесты экрана на все шесть настроек, на ввод текстом и на опечатку, не сбрасывающую диалог; интеграционный тест на то, что поднятая среди дня норма действует только назавтра.

- [x] **T-045. Статистика**
  `usecase/stats` + `/stats`: выучено, в работе, впереди, «уже знаю», серия дней, точность за 7 и 30 дней, прогноз нагрузки на неделю. Считается по всем активным курсам сразу — «сколько я знаю» вопрос про человека, а не про колоду; курсы на паузе и в архиве не в счёт. Прогноз раскладывается по границам суток пользователя, а не сложением часов: в день перевода часов он бы съехал. Строки, за которыми ничего нет, опускаются — «серия 0 дней» у того, кто не отвечал, это упрёк, а не факт. Заодно к сессии подключён журнал повторений: без него точность в итоге занятия молча не показывалась.
  **DoD:** юнит-тесты на подсчёт по фазам, пропуск курсов на паузе, раскладку прогноза по дням пользователя (просроченное — в сегодня), точность за два периода порознь, серию дней таблицей случаев; тесты экрана на состав сводки и на опускаемые строки.

- [ ] **T-046. Планировщик и outbox** ⭐
  `robfig/cron` с тиком в 5 минут, отбор пользователей по локальному времени, вставка в `outbox_notifications` в транзакции, `pg_try_advisory_lock` против дублей при нескольких инстансах.
  **DoD:** тесты с подменённым `Clock`: напоминание ставится ровно один раз за день, при рестарте не дублируется, для пользователей на паузе не ставится.

- [ ] **T-047. Рассылка**
  Воркер-пул, отправка неотправленных из outbox, ограничитель скорости (~25 сообщений/с суммарно), обработка блокировки бота пользователем (`403` → деактивация).
  **DoD:** тест ограничителя; при `403` пользователь помечается неактивным и рассылка продолжается.

- [ ] **T-048. `/pause` и `/delete_me`** ∥
  Пауза обучения и полное удаление данных пользователя с подтверждением.
  **DoD:** интеграционный тест: после удаления в БД не остаётся строк, связанных с пользователем.

## M9 — Продакшен

Детали решений — в [DEPLOY.md](./DEPLOY.md).

- [ ] **T-049. Наблюдаемость**
  `/healthz` (пул БД + время последнего успешного polling-цикла) и `/metrics` Prometheus (апдейты, ответы по режимам, задержки БД, ошибки Telegram API) на локальном интерфейсе. Алерты в админский чат (`ADMIN_CHAT_ID`): паника, ошибка миграции, серия ошибок Telegram API.
  **DoD:** метрики отдаются, healthcheck краснеет при погашенной БД, тестовый алерт доходит в админский чат.

- [ ] **T-050. Сборка образа**
  Многостадийный `Dockerfile` (distroless, статическая сборка, non-root), `.dockerignore`, публикация в GHCR из CI с тегами `sha-<полный SHA>` и `latest`, кеш сборки через `type=gha`.
  **DoD:** образ < 30 МБ, запускается из чистого окружения, в CI собирается за разумное время на кеше.

- [ ] **T-051. Подготовка VPS**
  Hetzner CX22 (или аналог), пользователь `deploy` в группе `docker`, `ufw` только на 22/tcp, unattended-upgrades, `/opt/lexi-bot` с `docker-compose.prod.yml` и `.env` (права `600`), ротация docker-логов (`max-size: 10m`, `max-file: 3`). Порт Postgres наружу не публикуется.
  **DoD:** бот поднят вручную одной командой и отвечает в Telegram; `nmap` снаружи видит только SSH.

- [ ] **T-052. Автодеплой**
  Джобы `image` и `deploy` в `ci.yml`: сборка и push в GHCR → SSH на VPS → `docker compose pull && up -d` → ожидание `/healthz`. `concurrency: deploy-production` без отмены, environment `production`, секреты `DEPLOY_HOST/USER/SSH_KEY`.
  **DoD:** merge в `main` доводит изменение до прода без ручных действий; намеренно сломанный старт приложения роняет джоб деплоя, а не проходит как успешный.

- [ ] **T-053. Бэкапы**
  Контейнер с ежедневным `pg_dump -Fc` → `rclone` в R2/B2, хранение 14 дневных + 8 недельных, локальная копия последнего дампа, уведомление об ошибке в админский чат.
  **DoD:** дамп появляется в хранилище; **выполнено учебное восстановление** в отдельную базу, интеграционные тесты против неё зелёные; процедура записана в `docs/RUNBOOK.md`.

- [ ] **T-054. RUNBOOK**
  `docs/RUNBOOK.md`: первый запуск, накат и откат релиза (тег образа), восстановление из бэкапа, ротация `BOT_TOKEN`, что делать при `409 Conflict`, при заполнении диска, при недоступности Telegram API.
  **DoD:** посторонний человек по инструкции разворачивает окружение с нуля.

- [ ] **T-055. Сквозной e2e-тест** ⭐
  Фейковый Telegram Bot API на `httptest` + Postgres: онбординг → `/learn` → ответы во всех трёх режимах → проверка сдвига `due_at` и записей в `reviews`.
  **DoD:** тест зелёный в CI и воспроизводим (никакого реального `time.Now()` и живой сети).

- [ ] **T-056. Проверка под нагрузкой**
  Скрипт, эмулирующий 100 пользователей, ведущих сессии одновременно; замер задержек и планов ключевых запросов.
  **DoD:** p95 обработки апдейта < 200 мс, отсутствуют sequential scan на `cards`, нет утечек соединений пула.

## Порядок и зависимости

```
M0 ──► M1 ──► M2 ──► M4 ──► M5 ──► M6 ──► M7 ──► M8 ──► M9
        │      │      ▲
        └──────┴─ M3 ─┘
```

M1 (домен) не зависит ни от чего и делается полностью в памяти — это лучшая точка входа
в проект: после неё вся логика обучения уже написана и протестирована, остальное
подключает её к миру. M3 (локализация) нужна к началу M4.

**Первая работающая версия — после T-034:** онбординг, встроенная колода-заглушка,
учебная сессия со всеми тремя режимами и настоящим SM-2. Всё дальнейшее наращивает
её без переделок.
